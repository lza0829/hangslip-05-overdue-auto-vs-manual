# 衣票墙（hangslip）

收衣贴号 → 工序推进 → 取衣核销关账 → 超期/丢失隔离互证。

- 前端 http://127.0.0.1:6200
- API http://127.0.0.1:11200

## 超期进隔离：唯一口径（全局只此一套）

本仓库对「超期进隔离听谁」采用**到点扫描落隔离为准**：

1. **扫描是唯一落定入口。** `POST /api/超期扫描` 把「承诺日 < 今日且仍为待取」的票逐张改入
   `超期隔离`，同时写入隔离流水（`quarantines.source='扫描'`，带 `scan_id`、`from_status`、
   `due_date`）和逐票扫描明细（`scan_items`）。人工点选 `超期隔离` 一律拒绝（409）。
2. **待取可见性、总览超期数、在途水位都由隔离结果推导。** 待取页只查 `status='待取'`；
   总览的 `超期待取数` 是尚未落隔离的待取超期票；水位按非终态口径（`已取`、`丢失隔离` 之外，
   含 `超期隔离`——衣仍在店内待处置）统计。扫描落定后待取页与超期数同步归零。
   一致性可用 `GET /api/超期扫描/核对` 从隔离流水 + 取衣记录重放并逐票比对。
3. **扫描与取衣争用同一把写锁。** 二者都在 `BEGIN IMMEDIATE` 事务里读「待取」再写终态，
   只有一方成功；扫描侧若发现票已被取衣，记一条 `跳过-已非待取` 明细，绝不改态。
   因此不会出现「已取又隔离」，争用结果在扫描记录里可核。
4. **日闸预检先行。** 结案前 `GET /api/日闸/预检` 必须满足：没有逾承诺日待取票、今日扫描已存在且
   已完成；否则 `POST /api/日闸/结案` 返回 409。

丢失隔离仍走人工点选（`POST /api/挂牌/{票号}/隔离` 且 `kind=丢失隔离`），与扫描流水共用同一张表，
以 `source` 字段区分，便于互证。丢失认领恢复不在本需求范围内。

## 本地开发

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\uvicorn app.main:app --host 127.0.0.1 --port 11200

cd ..\frontend
npm install
npm run dev
```

后端测试（含扫描/取衣争用与日闸预检）：

```bash
cd backend
.venv/bin/python -m pytest tests -q
```
